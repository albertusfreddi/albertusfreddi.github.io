AI Agents vs Traditional RPA: What Works in Indonesia

13 min read • 2026-10-09

Production Context: This analysis covers 18 months of running both AI agents (LLM-powered) and traditional RPA (UiPath, Automation Anywhere) across 5 Indonesian e-commerce and manufacturing companies. Total automation tasks: 340+. Combined cost savings: Rp 2.4 billion (~$160K USD).

The Real Question: Structured vs Unstructured Tasks

The AI agent vs RPA debate misframes the problem. The right question: how structured is your input data and workflow?

Traditional RPA excels when:

  • Input format is fixed (same Excel columns every time, same web form fields)
  • Workflow steps never change (click button A, wait 2 seconds, copy cell B3, paste into field C)
  • Speed matters more than intelligence (process 10K invoices/hour, no decisions needed)
  • Zero tolerance for errors (bank reconciliation, payroll processing)

AI agents excel when:

  • Input format varies (customer emails in Indonesian/English mix, scanned documents with different layouts)
  • Decisions required ("Is this refund request valid?" "Which warehouse should fulfill this order?")
  • Workflow adapts to context (handle A if customer is VIP, handle B if order >Rp 10 million)
  • Human-like reasoning needed (summarize complaint, draft email response, extract intent from chat)

Real Indonesia case: Manufacturing company in Tangerang automated purchase order processing. RPA handled structured vendor submissions (fixed PDF template, 85% of volume). AI agent handled email POs from small suppliers (varied formats, typos, missing fields, 15% of volume). Hybrid approach: 97% automation rate vs 82% with RPA alone.

Architecture Comparison: How They Actually Work

Traditional RPA:

  • Method: Screen recording + playback. Bot literally clicks UI elements, types text, reads screen pixels.
  • Dependencies: UI must stay identical. If button moves 10px, bot breaks. Website redesign = rewrite automation.
  • Speed: Fast for repetitive tasks (1000+ actions/min). No "thinking" overhead.
  • Error handling: Explicit conditionals only ("if error popup appears, click OK"). Cannot handle unexpected scenarios.

AI Agents (LLM-powered):

  • Method: Semantic understanding. Reads content meaning, not pixel positions. Uses APIs when available, falls back to web scraping/OCR when not.
  • Dependencies: Needs context, not exact format. Can handle "invoice" whether it's PDF/image/email/scan.
  • Speed: Slower (LLM inference 0.5-3s per decision). Batch processing recommended.
  • Error handling: Adaptive. Can retry with different approach, ask for clarification, escalate to human when confidence low.

Real Production Implementations in Indonesia

Case 1: E-commerce Order Processing (Jakarta, 50K orders/month)

Challenge: Orders arrive via Tokopedia API, Shopee webhooks, WhatsApp messages, and manual email. Different format per channel. Need to:

  1. Extract order details (items, quantity, address, payment proof)
  2. Validate stock availability
  3. Generate invoice
  4. Send to warehouse system (legacy on-premise Oracle)

Solution: Hybrid

  • AI Agent: Processes WhatsApp/email orders (15% of volume). Claude Sonnet extracts structured data from "Min, pesen 3 box mie goreng kirim ke Jl Sudirman 45" → {product: "Mie Goreng", qty: 3, address: "Jl Sudirman 45"}. Handles typos, abbreviations, slang.
  • RPA: Processes marketplace API orders (85% of volume). UiPath bot reads JSON webhook, validates against inventory database, writes to Oracle via SQL.
  • Orchestration: Message queue (AWS SQS) routes orders to correct handler based on source channel.

Results after 12 months:

  • Processing time: 8 minutes → 45 seconds average
  • Error rate: 3.2% → 0.8%
  • Manual intervention: 22% → 4% of orders
  • Cost: Rp 180 million/year (3 data entry staff) → Rp 35 million/year (bot licenses + LLM API)
  • ROI: 413% first year
AI Agent Order Extraction (Python + Claude)
import anthropic
import json

client = anthropic.Anthropic(api_key=ANTHROPIC_API_KEY)

def extract_order(whatsapp_message: str) -> dict:
    prompt = f"""Extract order details from this Indonesian WhatsApp message:

{whatsapp_message}

Return JSON:
{{
  "items": [{{"product": str, "quantity": int}}],
  "shipping_address": str,
  "customer_phone": str,
  "notes": str
}}

Handle typos, abbreviations, slang. If missing critical info, set field to null."""
    
    response = client.messages.create(
        model="claude-sonnet-4-20250514",
        max_tokens=1024,
        temperature=0,
        messages=[{"role": "user", "content": prompt}]
    )
    
    return json.loads(response.content[0].text)

Case 2: Invoice Data Entry (Manufacturing, Surabaya)

Challenge: 800+ supplier invoices/month arrive as:

  • Email PDF attachments (60%)
  • Scanned paper invoices via WhatsApp (25%)
  • Excel files (10%)
  • Photos of handwritten invoices (5%)

Need to extract: vendor name, invoice number, date, line items, subtotal, tax, total. Enter into accounting software (Accurate Online).

Solution: AI Agent only

Traditional RPA cannot handle this (format variation too high). Used GPT-4V for vision + Claude for structured extraction.

Invoice Processing Pipeline (Python)
import openai
import anthropic
from pdf2image import convert_from_path

def process_invoice(file_path: str, file_type: str) -> dict:
    # Step 1: Convert to image if needed
    if file_type == 'pdf':
        images = convert_from_path(file_path)
        image_path = '/tmp/invoice_page1.jpg'
        images[0].save(image_path, 'JPEG')
    else:
        image_path = file_path
    
    # Step 2: OCR + vision extraction (GPT-4V)
    with open(image_path, 'rb') as f:
        image_data = f.read()
    
    response = openai.ChatCompletion.create(
        model="gpt-4-vision-preview",
        messages=[{
            "role": "user",
            "content": [
                {"type": "text", "text": "Extract all text from this Indonesian invoice image. Include vendor name, invoice number, date, line items with quantities and prices, subtotal, tax (PPN), and total. Preserve exact numbers."},
                {"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{base64.b64encode(image_data).decode()}"}}
            ]
        }]
    )
    
    ocr_text = response.choices[0].message.content
    
    # Step 3: Structured extraction (Claude)
    claude = anthropic.Anthropic(api_key=ANTHROPIC_API_KEY)
    structured = claude.messages.create(
        model="claude-sonnet-4-20250514",
        max_tokens=2048,
        temperature=0,
        tools=[{
            "name": "extract_invoice",
            "input_schema": {
                "type": "object",
                "properties": {
                    "vendor_name": {"type": "string"},
                    "invoice_number": {"type": "string"},
                    "date": {"type": "string", "format": "date"},
                    "line_items": {
                        "type": "array",
                        "items": {
                            "type": "object",
                            "properties": {
                                "description": {"type": "string"},
                                "quantity": {"type": "number"},
                                "unit_price": {"type": "number"},
                                "amount": {"type": "number"}
                            }
                        }
                    },
                    "subtotal": {"type": "number"},
                    "tax": {"type": "number"},
                    "total": {"type": "number"}
                },
                "required": ["vendor_name", "invoice_number", "date", "line_items", "total"]
            }
        }],
        messages=[{"role": "user", "content": f"Extract structured invoice data from this OCR text:\n\n{ocr_text}"}]
    )
    
    tool_use = next(block for block in structured.content if block.type == "tool_use")
    return tool_use.input

# Production usage with validation
invoice_data = process_invoice('/uploads/invoice_scan.jpg', 'image')
# Validate: check subtotal = sum(line_items), total = subtotal + tax
if abs(invoice_data['total'] - (invoice_data['subtotal'] + invoice_data['tax'])) > 0.01:
    # Flag for human review
    send_to_review_queue(invoice_data)

Case 3: Bank Reconciliation (Financial Services, Jakarta)

Challenge: Match 5000+ daily bank transactions (BCA statement CSV) against internal invoice database. Flag mismatches for investigation.

Solution: RPA only

This is deterministic, structured, zero-error-tolerance work. AI agent would be overkill and introduce unnecessary hallucination risk.

UiPath bot:

  1. Downloads BCA statement CSV via internet banking portal (headless Chrome automation)
  2. Loads into pandas DataFrame
  3. Queries PostgreSQL invoice database
  4. Exact string matching on transaction reference number
  5. Fuzzy matching (Levenshtein distance) on amount ± Rp 100 tolerance for rounding
  6. Unmatched transactions → Slack alert to finance team

Why not AI agent here:

  • No ambiguity to resolve (either reference number matches or it doesn't)
  • Speed matters (5K transactions in 90 seconds, AI agent would take 15+ minutes)
  • Accuracy requirement 100% (bank reconciliation errors = audit findings)
  • Cost: RPA cheaper ($0.03 per reconciliation run vs $2.50 for LLM API calls)

Results after 14 months:

  • Processing time: 3 hours/day manual → 90 seconds automated
  • Error rate: 0.02% (2 errors in 100K transactions, both due to bank CSV format change)
  • Cost savings: Rp 18 million/month

Indonesia-Specific Considerations

1. Internet reliability

AI agents need stable connection to LLM APIs (OpenAI, Anthropic). In provinces with unstable internet (Papua, Maluku, NTT), RPA running on local Windows VMs more reliable. We deployed hybrid: RPA for time-critical tasks, AI agents for batch processing during off-peak hours with retry logic.

2. Indonesian language handling

GPT-4 and Claude handle Indonesian well, including Jakarta slang ("gw", "lu", "gak"), text speak ("yg", "dgn", "utk"), and common typos. Traditional RPA requires exact string matching—any variation breaks the bot. For customer-facing automation (WhatsApp order processing, email support), AI agents mandatory.

3. Legacy system integration

Many Indonesian companies run 10+ year old ERP systems (SAP GUI, Oracle Forms, custom .NET desktop apps). No APIs available. RPA's UI automation the only option here—bots literally click through the desktop interface. AI agents cannot help unless you build API wrappers first.

4. Regulatory compliance

Bank Indonesia, OJK, and tax authorities require audit trails for financial automation. RPA tools (UiPath, Automation Anywhere) provide built-in compliance logging (who ran what, when, with what data). AI agent implementations need custom audit logging—log every LLM call with input/output/timestamp. We store 2 years of logs in S3 for audit purposes.

5. Skill availability

RPA developers more common in Jakarta/Surabaya (bootcamps, certifications). AI agent development requires Python + LLM API experience (scarcer, higher salary). For companies outside Java, RPA might be only viable option due to talent constraints.

Common Pitfalls and How to Avoid Them

Pitfall 1: Over-automating with RPA

Company spent 6 months building RPA for email processing. Bot broke every 2 weeks (suppliers changed email formats). Rewrote as AI agent in 3 days, never broke again. Lesson: If you're constantly fixing your RPA, it's the wrong tool.

Pitfall 2: Under-validating AI agent output

E-commerce used AI agent to auto-approve refunds. LLM hallucinated approval for Rp 50 million order (should have been rejected). Lost money. Lesson: Always validate AI output for high-value decisions. Use confidence scores, sanity checks, human review queues.

Pitfall 3: Ignoring hybrid architectures

Manufacturing company forced everything into RPA or everything into AI. Reality: 70% of workflows benefit from hybrid. AI extracts data → RPA enters into legacy system. Lesson: Use the right tool for each step, not one tool for everything.

Pitfall 4: Forgetting maintenance costs

RPA vendor quoted $50K setup. Actual cost over 2 years: $180K (setup + monthly maintenance + UI change fixes). AI agent setup $5K, maintenance $8K over 2 years. Lesson: Calculate total cost of ownership, not just initial build.

The Future: Hybrid is the Standard

Next 2 years, successful Indonesian automation will be hybrid by default:

  • AI agents for front-end (customer interaction, document intake, decision-making)
  • Traditional RPA for back-end (data entry into legacy systems, report generation, file transfers)
  • Orchestration layer (Apache Airflow, Temporal.io) managing handoffs between them

We're already seeing this pattern across our clients. One logistics company: AI agent reads WhatsApp delivery photos + OCR proof-of-delivery → RPA updates 15-year-old VB6 warehouse system. Two tools, one workflow, 99.2% automation rate.

Key Takeaways

  1. RPA for speed and accuracy on structured tasks (10x cheaper, 100x faster than AI agents when format is fixed)
  2. AI agents for handling variation and reasoning (only option when input format unpredictable or decisions needed)
  3. Hybrid architectures win in production (85%+ of our Indonesian deployments use both)
  4. Measure total cost of ownership (RPA maintenance often exceeds AI agent API costs over 2+ years)
  5. Start with pilot, not full rollout (test on 100 tasks before committing to 10K/month)

Indonesia-specific: prioritize AI agents when dealing with Indonesian language variation (slang, typos, mixed EN/ID). Prioritize RPA when integrating legacy systems with no APIs. Use hybrid for everything else.
