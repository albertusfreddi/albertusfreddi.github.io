Last year I got a call from the operations manager of a 4-star hotel in South Jakarta. Peak season was approaching — the kind where lobby queues snake out to the parking lot — and their front desk team was drowning. The average check-in was taking 12 minutes. For a 180-room property, that math doesn't work.

They had tried a cloud PMS before. It helped with reservations but did nothing for the physical bottleneck: staff still had to manually verify bookings, cross-check OTA data, re-enter guest IDs, and print room keys one at a time. Three systems, zero integration.

"We're not looking for a full replacement. We just want the staff to stop doing stupid repetitive things before a guest arrives."

That framing — remove the stupid repetitive things — is exactly the right way to scope an automation project. I want to walk through how we got there.

The Real Problem Was Upstream

Most hotels think check-in is slow because front desk staff aren't fast enough. That's almost never true. The real delay is what happens before the guest touches the desk.

When a guest books through Booking.com, Agoda, or Traveloka, that booking lands in a channel manager, which syncs (imperfectly) to the PMS, which the staff checks manually when the guest arrives. At this hotel, that chain had three known failure points:

  • OTA rate discrepancy — Booking.com prices sometimes didn't match what the PMS showed, causing staff to call reservations mid-check-in
  • Incomplete guest data — OTA bookings rarely included ID numbers, which Indonesian law requires for hotel registration
  • Manual key encoding — the key card system was standalone; staff had to encode each card separately after room assignment

None of these are technology problems in the exciting sense. They're data pipeline failures. The fix wasn't AI — it was plumbing.

What We Built

1. Pre-arrival Data Aggregation

We built a Python service that runs nightly and pulls tomorrow's arrivals from every booking channel via API (Booking.com, Agoda, direct website). It normalizes all fields into a single schema and flags missing data — specifically, any reservation where guest ID or phone number is blank.

For flagged reservations, an automated WhatsApp message goes out the night before asking guests to complete their registration. By the time they walk in, 70% of incomplete records are already resolved.

Python — nightly pre-arrival sync (simplified)
def sync_arrivals(date: str) -> list[Reservation]:
    sources = [
        booking_com_client.get_arrivals(date),
        agoda_client.get_arrivals(date),
        direct_db.query_arrivals(date),
    ]
    merged = merge_and_deduplicate(sources)

    for res in merged:
        if not res.guest_id or not res.phone:
            whatsapp.send_pre_checkin_link(res)
            res.status = "pending_completion"

    return merged

2. Room Assignment Pre-processing

Room assignment was previously done at check-in time, when staff had to balance room type, floor preference, and availability simultaneously under pressure. We moved this to a morning housekeeping sync: a script reads room status from the PMS (clean/dirty/inspected) and runs a simple assignment algorithm two hours before check-in time begins.

The algorithm isn't sophisticated — it's basically sorted priority queues — but it works for a property this size. The important thing is that by 1 PM, every arriving guest already has a pre-assigned room. Staff can override it, but rarely need to.

3. Key Card Encoding Queue

The key card system had a serial port interface — old hardware, but it had documentation. We wrote a driver in Python that reads the pre-assigned room list and pre-encodes keys during the quiet period before check-in. Keys sit labeled in a tray. When a guest arrives and is verified, staff just hand over the labeled envelope.

This step alone cut 3–4 minutes per check-in.

The Results After 60 Days

4.8m avg check-in time (was 12.2m)
70% guest data complete pre-arrival
0 key card encoding errors (was ~8/week)

The front desk team was skeptical at first — people usually are when you automate something they've been doing manually for years. After the first peak weekend, the operations manager sent me a WhatsApp photo of an empty lobby queue at 3 PM on a Saturday. That was enough.

What Made This Work (and What Would Have Killed It)

What worked

  • Narrow scope — We didn't try to replace the PMS or the channel manager. We filled the gaps between them.
  • Data first — The pre-arrival WhatsApp message was the highest-impact thing we did, and it cost almost nothing to build.
  • Staff buy-in — We demoed the system to front desk staff before go-live, incorporated their feedback, and made sure overrides were always possible.
  • Gradual rollout — We ran the automation in "shadow mode" for two weeks (it ran but didn't actually send messages or encode keys) to catch edge cases.

What almost killed it

  • API rate limits — Booking.com's API has strict rate limits. Our first sync script hit them on day two. We rewrote it with exponential backoff and off-peak scheduling.
  • Edge cases in OTA data — Some OTAs send check-in dates in UTC, others in local time. This caused a few guests to appear on the wrong day's list until we standardized timezone handling.
  • Serial port reliability — The key card encoder occasionally dropped the connection. We added a health check and automatic reconnect; now it's been stable for two months.

The Bigger Lesson

Hospitality automation in Indonesia is still mostly about integrating systems that should have been integrated years ago. The bottlenecks aren't front desk speed or staff competence. They're data silos, manual handoffs, and software that was bought piecemeal without thinking about the full workflow.

You don't need enterprise software to fix this. You need someone who understands both the business process and how to write code that talks to multiple systems at once.

If your hotel, resort, or F&B operation has a process that involves staff doing the same thing repeatedly — copying from one screen to another, re-entering data, waiting for a system to sync — there's almost certainly a Python script that can take that off their plate.

This project took about 6 weeks from first meeting to stable production. Total cost was a fraction of any off-the-shelf enterprise solution, and the property now owns the code outright.
